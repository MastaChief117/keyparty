Security

How we protect your keys, your requests, and your sanity.

Encryption

All API keys are encrypted at rest with AES-256-GCM:

  • 32-byte master key stored in .gateway.key (chmod 0600)
  • Each key gets a random 12-byte nonce per encryption
  • Keys are decrypted in-memory only when needed for provider requests
  • Master key derived from SHA-256 hash of key file contents
Important: If you lose .gateway.key, your API keys are gone forever. Back it up securely.

Authentication

Unified API Key

Your clients authenticate with Authorization: Bearer <unified-key>. The key is decrypted to look up the provider, then used for the provider request.

Admin Authentication

Admin endpoints require either:

  • X-Admin-Key: <password> header
  • Authorization: Bearer <password> header

Brute-Force Protection

After 5 failed admin auth attempts from the same IP:

  • IP is blocked for 1 hour
  • All subsequent requests from that IP return 403
  • Block status tracked in memory (resets on restart)

Prompt Firewall

Block or redact outbound requests that contain sensitive data before they reach providers.

Features

  • PII Detection: Emails, phone numbers, SSNs, credit card numbers
  • Secret Detection: API keys, tokens, passwords in prompt content
  • Custom Patterns: Regex-based rules for organization-specific patterns
  • Actions: Block the request entirely, or redact matched content

Configuration

curl -X PUT http://localhost:8080/admin/firewall \
  -H "Authorization: Bearer your-admin-password" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "block_pii": true,
    "block_secrets": true,
    "action": "block"
  }'

IP Allowlist

Restrict which IPs can use a specific API key.

curl -X POST http://localhost:8080/admin/ip-allowlist \
  -H "Authorization: Bearer your-admin-password" \
  -H "Content-Type: application/json" \
  -d '{
    "key_id": 1,
    "allowed_ips": ["192.168.1.0/24", "10.0.0.1"]
  }'

Requests from non-allowed IPs get a 403 Forbidden.

Virtual Key Security

  • Virtual keys are prefixed with vk- to distinguish from real keys
  • Monthly token budget enforcement
  • Per-minute rate limiting
  • Model allowlist per key
  • Usage tracking with cost estimation

SSRF Protection

The gateway validates all outbound requests to prevent Server-Side Request Forgery:

  • Provider URLs are validated before requests
  • Private/internal IPs are blocked from provider targets
  • Only configured provider base URLs are allowed

What We Don't Do

  • We don't store plaintext API keys
  • We don't send your data anywhere except the configured providers
  • We don't phone home or track you
  • We don't use cookies or sessions
  • We don't have analytics or telemetry
That's the whole security model. Encrypt at rest, authenticate on access, firewall outbound, allowlist IPs. No complexity theater.
