Core Components

Gateway Router (proxy/proxy.go)

The main request handler. All requests flow through here:

  1. Parse Authorization header, decrypt the API key
  2. Look up the provider from the key
  3. Apply provider/model override headers if present
  4. Check virtual key rate limits and budgets
  5. Check provider token budgets
  6. Check IP allowlist
  7. Forward request to provider, stream response back
  8. If 402/429 and failover is enabled, retry with backup provider
  9. If compaction enabled, summarize chat history on failover
  10. Log everything to SQLite

Auth Layer (auth/auth.go)

  • Unified Key: Authorization: Bearer <key> — decrypted via AES-256-GCM
  • Admin: X-Admin-Key header — plain-text comparison
  • Virtual Keys: vk- prefix — checked against DB with budget/rate limits
  • IP Allowlist: Optional per-key IP restriction

AES Store (store/store.go)

All API keys are encrypted with AES-256-GCM:

  • 32-byte master key stored in .gateway.key (chmod 0600)
  • Key is derived from a SHA-256 hash of the key file contents
  • Each API key gets a random 12-byte nonce per encryption
  • Keys are never stored in plaintext — not even in memory after decryption

Provider Client (provider/provider.go)

HTTP clients for each provider with provider-specific logic:

  • 10 built-in providers + custom provider support
  • Each provider has: base URL, model mapping, auth header format
  • Gemini uses special alt=sse endpoint for streaming
  • Groq uses OpenAI-compatible endpoint
  • Each provider has its own timeout and retry settings

Failover Engine (proxy/proxy.go)

Triggers automatically on 402 (quota) or 429 (rate limit):

  1. Records current provider as failed
  2. Looks up configured backup provider
  3. If compaction enabled, summarizes chat history via backup model
  4. Retries request with backup provider
  5. Cache compacted result to avoid re-compacting same conversation

Virtual Keys

Share access without sharing real API keys:

  • vk- prefix identifies virtual keys
  • Monthly token budget and cost tracking
  • Per-key rate limiting (requests per minute)
  • Model allowlist per key
  • Usage tracking: requests, tokens, estimated cost

Tech Stack

ComponentTechnology
LanguageGo 1.24+
DatabaseSQLite (via modernc.org/sqlite — pure Go, no CGO)
EncryptionAES-256-GCM (standard library)
HTTPStandard library net/http
StreamingSSE (Server-Sent Events) via bufio.Scanner
DashboardEmbedded HTML/JS SPA (no framework)
DeploymentSingle binary (~16MB), no dependencies

Why Single Binary?

  • No Docker required. Just go build and run.
  • No Node.js. Dashboard is plain HTML/JS embedded in the binary.
  • No external database. SQLite is embedded.
  • Cross-compile. Build for Linux, macOS, Windows from any machine.
  • One file to deploy. Copy the binary and .gateway.key to any server.
That's the whole architecture. It's simpler than you'd expect. The entire codebase is ~25 files. No microservices. No message queues. Just Go handling HTTP requests and talking to SQLite.
