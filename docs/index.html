what it actually does

all the stuff you'd build yourself if you had time. which you don't.

⚡

multi-provider routing

one endpoint for openai, anthropic, gemini, groq, nvidia, together, deepseek, openrouter, fireworks, mistral.

🔄

provider/model override

send X-Gateway-Provider header to route any request to any saved provider. override the model too.

🔄

compaction failover

provider dies? chat history gets summarized by a cheap model and rerouted. user never sees the 429.

🎲

provider race

same prompt to 5 providers at once. first response wins. great for finding the fastest/cheapest.

👤

virtual keys

give each user their own key with budgets, rate limits, and model restrictions. no more shared key chaos.

💰

cost tracking

see exactly how much you're spending per provider, per model, per day. no more surprise bills (there were no surprise bills, you have $4).

🔒

encryption

AES-256-GCM for all keys at rest. master key with 0600 perms. standard go crypto, not my own crypto.

🛡

guardrails

PII detection, prompt injection blocking, custom regex rules. keep your users safe-ish.

🔄

auto-rotate keys

picks the healthiest key per provider automatically. one less thing to wake up at 3am for.

🎬

ai rumble

two providers roast each other in real-time via SSE. exactly as chaotic as it sounds.

🎷

rap battle

two AIs drop bars with context memory across rounds. gpt-4 vs claude, who wins?

💬

model roulette

picks a random provider for your message. live dangerously.

get started. like, now.

no docker. no npm. no kubernetes. just a binary.

terminal
# clone and build git clone https://github.com/MastaChief117/keyparty.git cd keyparty go build -o keyparty . # run it ./keyparty -port 8080 -admin-pass your-password # open dashboard: http://localhost:8080 # add your API keys there. done.
provider override
# force a specific provider (bypass auto-routing) curl localhost:8080/v1/chat/completions \ -H "Authorization: Bearer gw-abc123" \ -H "X-Gateway-Provider: gemini" \ -d '{"model":"gpt-4o","messages":[...]}' # ^ sends to gemini even though model says gpt-4o # override provider AND model name curl localhost:8080/v1/chat/completions \ -H "Authorization: Bearer gw-abc123" \ -H "X-Gateway-Provider: nvidia" \ -H "X-Gateway-Model: nvidia/nemotron-3-nano-30b-a3b" \ -d '{"model":"anything","messages":[...]}' # ^ the model field in body doesn't matter, header wins
failover setup
# when groq rate-limits you (it will): # 1. chat history gets summarized (compacted) # 2. request reroutes to backup provider # 3. user gets a response. conversation survives. # configure via API (or dashboard): curl -X POST localhost:8080/admin/failover \ -H "Authorization: Bearer your-admin-pass" \ -d '{"key":"enabled","value":"true"}' curl -X POST localhost:8080/admin/failover \ -H "Authorization: Bearer your-admin-pass" \ -d '{"key":"triggers","value":"402,429"}' curl -X POST localhost:8080/admin/failover \ -H "Authorization: Bearer your-admin-pass" \ -d '{"key":"compact","value":"true"}' curl -X POST localhost:8080/admin/failover \ -H "Authorization: Bearer your-admin-pass" \ -d '{"key":"provider","value":"gemini"}'
virtual keys
# give each user their own key with limits curl -X POST localhost:8080/admin/virtual-keys \ -H "Authorization: Bearer your-admin-pass" \ -d '{ "name": "free-tier-user", "monthly_budget": 5, "rate_limit": 10, "allowed_models": ["gpt-4o-mini", "claude-3-haiku"] }' # user gets a vk- key. use it like a regular API key. curl localhost:8080/v1/chat/completions \ -H "Authorization: Bearer vk-abc123" \ -d '{"model":"gpt-4o-mini","messages":[...]}'
python (openai SDK)
from openai import OpenAI client = OpenAI( base_url="http://localhost:8080/v1", api_key="gw-your-unified-key" ) # default routing response = client.chat.completions.create( model="gpt-4o", messages=[{"role": "user", "content": "hello"}] ) # override provider with header # (use httpx or requests for custom headers) import requests resp = requests.post( "http://localhost:8080/v1/chat/completions", headers={ "Authorization": "Bearer gw-your-key", "X-Gateway-Provider": "groq", }, json={ "model": "gpt-4o", "messages": [{"role": "user", "content": "hello"}] } )

FAQ

the questions people ask.

what is this thing?▼
an AI gateway for broke devs. one endpoint, ten providers, zero budget. you have 5 free tiers and no money. this makes them work together.
how much does it cost?▼
free. MIT license. no "enterprise tier." no "contact sales." you just pay for whatever API keys you use.
what happens when a provider dies?▼
it fails over. chat history gets summarized and rerouted. your user never sees the error. we're basically life support for your conversations.
is my data safe?▼
AES-256-GCM encryption at rest. standard go crypto libraries. no hand-rolled crypto. gateway doesn't store your messages. see the security docs.
does it work with cursor/claude code/etc?▼
yes. it's openai-compatible. point any tool that supports custom base URLs at the gateway.
can i run this on a raspberry pi?▼
yes. it's a single 16MB binary. idle memory is 13MB. it'll run on a potato if the potato has go installed.
can two AIs roast each other?▼
yes. AI Rumble and Rap Battle are built in. two providers go head-to-head via SSE streaming. it's as chaotic as it sounds.
what's the catch?▼
there is no catch. free, open source, MIT. we just vibes.
