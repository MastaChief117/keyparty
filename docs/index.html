Provider/Model Override

Compaction Failover

Quick Start

Up and running in 30 seconds. No Docker. No npm. No JavaScript gods.

terminal
# Clone and build git clone https://github.com/MastaChief117/keyparty.git cd keyparty go build -o keyparty . # Run it ./keyparty -port 8080 -admin-pass your-password # Dashboard: http://localhost:8080 # Add your API keys in the dashboard, then start making requests.
provider override
# Default routing — auto-matches model to provider curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer YOUR_KEY" \ -d '{"model":"llama-3.3-70b-versatile","messages":[...]}' # Override provider — same request goes to Gemini instead curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer YOUR_KEY" \ -H "X-Gateway-Provider: gemini" \ -d '{"model":"llama-3.3-70b-versatile","messages":[...]}' # Override both provider and model curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer YOUR_KEY" \ -H "X-Gateway-Provider: nvidia" \ -H "X-Gateway-Model: nvidia/nemotron-3-nano-30b-a3b" \ -d '{"model":"llama-3.3-70b-versatile","messages":[...]}'
failover & compaction
# When your primary provider returns 429 or 402: # 1. Chat history is summarized by a cheap provider (compaction) # 2. Request is rerouted to the configured backup provider # 3. User gets a response — conversation survives # Configure via dashboard or API: curl -X POST http://localhost:8080/admin/failover \ -H "Authorization: Bearer ADMIN_PASS" \ -d '{"key":"enabled","value":"true"}' curl -X POST http://localhost:8080/admin/failover \ -H "Authorization: Bearer ADMIN_PASS" \ -d '{"key":"triggers","value":"402,429"}' curl -X POST http://localhost:8080/admin/failover \ -H "Authorization: Bearer ADMIN_PASS" \ -d '{"key":"compact","value":"true"}' curl -X POST http://localhost:8080/admin/failover \ -H "Authorization: Bearer ADMIN_PASS" \ -d '{"key":"provider","value":"gemini"}'
virtual keys
# Virtual keys give you per-consumer control: # - Monthly budget limits # - Rate limiting (requests per minute) # - Model allowlists (which models they can use) # Create via dashboard or API: curl -X POST http://localhost:8080/admin/virtual-keys \ -H "Authorization: Bearer ADMIN_PASS" \ -d '{"name":"my-app-user","monthly_budget":10,"rate_limit":10,"allowed_models":["gpt-4o","claude-sonnet-4-5"]}' # Use the virtual key like a regular API key: curl http://localhost:8080/v1/chat/completions \ -H "Authorization: Bearer vk-your-virtual-key" \ -d '{"model":"gpt-4o","messages":[...]}'

Frequently Asked Questions

What is KeyParty?▼
An AI gateway for broke devs. One endpoint, ten providers, zero budget. It routes your requests across multiple LLM providers, handles failover, and tracks costs.
How much does it cost?▼
Free. MIT license. No "enterprise tier," no "contact sales." You just pay for your API keys to the providers you use.
What happens when a provider dies?▼
It fails over to another one. Chat history is compacted (summarized) to fit cheaper provider limits. Your conversation survives. We're basically life support for your chats.
Is my data safe?▼
AES-256-GCM encryption at rest for all API keys. Standard Go crypto libraries. No hand-rolled crypto. Gateway doesn't store your messages. See the full threat model in our security docs.
Can I use this with Claude Code / Cursor / other tools?▼
Yes. KeyParty is OpenAI-compatible. Point any tool that supports custom API base URLs at your gateway endpoint.
Can I run this on a Raspberry Pi?▼
Yes. It's a single 16MB Go binary. It'll run on anything that compiles Go. Idle memory is 13MB.
Can two AIs roast each other?▼
Yes. AI Rumble and Rap Battle are built in. Two providers go head-to-head via SSE streaming. It's exactly as chaotic as it sounds.
What's the catch?▼
There is no catch. It's free, open source, MIT license. We just vibes.
